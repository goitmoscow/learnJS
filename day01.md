## 2. const и let

По умолчанию используем const: запрет случайного переназначения помогает заметить ошибку. Если значение потребуется переназначать, выбираем let. Третий способ объявления — var; его нужно узнавать в чужом коде. Области видимости и поведение до объявления разберём в день 2.

Значение справа от = вычисляется, затем сохраняется в переменной слева.

```javascript
const price = 150;
let quantity = 2;
quantity = quantity + 1;
console.log(price * quantity);
```

Ожидаемый вывод:

```text
450
```

## 3. Все восемь типов данных

Тип относится к значению. В JavaScript **восемь типов**: семь примитивных и объектный. У переменной с `let` при переназначении может оказаться значение другого типа:

```javascript
let value = 42;
console.log(typeof value);
value = "42";
console.log(typeof value);
```

Ожидаемый вывод:

```text
number
string
```

| Тип | Для чего нужен | Пример значения | Результат typeof |
| --- | --- | --- | --- |
| number | Числа, расчёты, измерения | `12.5` | `"number"` |
| string | Текст, имена, сообщения | `"Маршрут"` | `"string"` |
| boolean | Ответ «да/нет», результат сравнения | `false` | `"boolean"` |
| undefined | Значение ещё не задано | `undefined` | `"undefined"` |
| null | Явно обозначенное отсутствие | `null` | `"object"` — исключение оператора |
| bigint | Точные целочисленные значения, в том числе большие | `42n` | `"bigint"` |
| symbol | Уникальная метка, в том числе ключ свойства | `Symbol("id")` | `"symbol"` |
| object | Связанные свойства одной сущности | `{ stops: 3 }` | `"object"` |

Первые семь строк — **примитивы**. `null` тоже примитив. Массивы и функции относятся к объектам; отдельными девятым и десятым типами они не являются. `typeof` возвращает строку и имеет особенности, которые разберём в разделе 7. [Типы и структуры данных в MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Data_structures).

### number, string и boolean

`number` используется и для целых, и для дробных чисел. `NaN` и бесконечности тоже имеют тип `number`. `string` хранит текст: число в кавычках становится текстовым значением. `boolean` имеет только два значения — `true` и `false`.

```javascript
console.log(typeof 42);
console.log(typeof "42");
console.log(typeof true);
```

Ожидаемый вывод:

```text
number
string
boolean
```

### undefined и null

Переменная `let`, которой ещё ничего не присвоили, содержит `undefined`. Значение `null` обычно явно задают, когда хотят обозначить отсутствие: например, пользователь пока не выбрал маршрут. Это два разных типа и два разных значения.

```javascript
let destination;
const selectedRoute = null;
console.log(destination);
console.log(selectedRoute);
console.log(destination === selectedRoute);
```

Ожидаемый вывод:

```text
undefined
null
false
```

### bigint: большие целочисленные ID из базы

У `number` ограничен диапазон **точного представления целых**: от `Number.MIN_SAFE_INTEGER` до `Number.MAX_SAFE_INTEGER`. За этими границами не каждое целое можно представить точно. Например, два разных ID из базы могут случайно стать одинаковыми после преобразования в `Number`.

Допустим, сервер передал большие целочисленные ID строками. Если нужно сравнить их как целые или сделать точное целочисленное вычисление, пригодится `BigInt`: это тип `bigint`. Создать значение можно из строки через `BigInt(...)` или литералом с `n` на конце.

```javascript
const idText = "9007199254740993";
const previousText = "9007199254740992";
console.log(Number(idText) === Number(previousText));
const id = BigInt(idText);
const previousId = BigInt(previousText);
console.log(id === previousId);
console.log(String(id + 1n));
```

Ожидаемый вывод:

```text
true
false
9007199254740994
```

Первое `true` показывает потерю различия в `Number`. При сравнении `BigInt` исходные ID различаются. Прибавление `1n` даёт следующее целое точно; `String` используется для вывода десятичной записи.

Если ID нужно только хранить и передавать, его можно оставить строкой. `BigInt` нужен для целочисленных операций, а не для любого текста из цифр. Дробного значения вроде `1.5n` не существует; обычная арифметика `1n + 1` вызовет ошибку — сначала нужно явно согласовать типы. Преобразование уже неточного `Number` в `BigInt` не восстановит потерянные цифры. Для обычного JSON согласуйте формат передачи, например строку. [Документация BigInt](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/BigInt).

### symbol: служебная метка без конфликта имён

Представьте приложение и расширение, которые работают с одним объектом пользователя. В приложении уже есть обычное поле `id`. Расширение может создать собственный символьный ключ и хранить служебное значение, не перезаписывая публичный `id`.

```javascript
const serviceId = Symbol("id");
const anotherServiceId = Symbol("id");
const user = { id: "public-42" };
user[serviceId] = "service-17";
console.log(user.id);
console.log(user[serviceId]);
console.log(serviceId === anotherServiceId);
```

Ожидаемый вывод:

```text
public-42
service-17
false
```

Обычное поле читается через `user.id`, служебное — через `user[serviceId]`. Для обращения к служебной метке нужна та же ссылка на символ. Два обычных вызова `Symbol("id")` создают **разные значения**: текст `"id"` — описание для человека, а не общий ключ. Подробно объекты и запись с квадратными скобками разберём в день 6.

Символьный ключ не делает данные секретными: его можно обнаружить через `Object.getOwnPropertySymbols`. Это средство предотвращения случайных конфликтов имён. [Документация Symbol](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Symbol).

### object: свойства одной сущности

Объект объединяет связанные данные: например, название маршрута и число остановок. Имена свойств позволяют обратиться к нужному значению. Массив — объект для упорядоченных элементов, функция — объект, который можно вызвать.

```javascript
const route = { name: "Центр", stops: 3 };
console.log(typeof route);
console.log(route.stops);
console.log(Array.isArray([]));
console.log(typeof console.log);
```

Ожидаемый вывод:

```text
object
3
true
function
```

Не путайте тип `object` и строку `"function"`, которую `typeof` возвращает для вызываемого объекта. Для проверки именно массива используйте `Array.isArray`. Работа с массивами будет в день 4, с объектами — в день 6.

## 4. Арифметика

Операторы +, -, *, / работают с числами. % возвращает остаток от деления.

Скобки позволяют явно задать порядок действий. Дробные вычисления могут иметь погрешность.

```javascript
const price = 120;
const count = 3;
console.log(price * count);
console.log((price * count) - 50);
console.log(7 % 2);
```

Ожидаемый вывод:

```text
360
310
1
```

## 5. Строка и число

Number преобразует значение в число, String в строку. Встроенные функции вызывают с круглыми скобками.

+ со строкой может склеивать текст. До расчёта явно преобразуйте текстовые числовые данные.

```javascript
console.log("12" + 3);
console.log(Number("12") + 3);
console.log(Number("кот"));
console.log(String(42));
```

Ожидаемый вывод:

```text
123
15
NaN
42
```

## 6. Сравнение значений

=== сравнивает без приведения типов. Результат сравнения имеет тип boolean.

= присваивает значение. == сравнивает с преобразованиями. Для первых задач используем === и !==.

```javascript
console.log(5 === 5);
console.log("5" === 5);
console.log(10 >= 8);
console.log(7 !== 7);
```

Ожидаемый вывод:

```text
true
false
true
false
```

## 7. Особенности typeof

Запустите примеры после таблицы типов. Результат typeof — строка; он не перечисляет типы языка без исключений.

```javascript
console.log(typeof null);
console.log(typeof 42n);
console.log(typeof Symbol("ticket"));
console.log(typeof []);
console.log(typeof console.log);
```

Ожидаемый вывод:

```text
object
bigint
symbol
object
function
```

## 8. Преобразование и числовые ограничения

Number пытается преобразовать всю строку; унарный + тоже выполняет числовое преобразование. Для ясности в первых решениях используйте Number. parseInt(text, 10) читает целый числовой префикс, parseFloat — дробный. Они могут принять начало строки и проигнорировать последующий текст: это не проверка корректности всей записи.

NaN означает неудачный числовой результат, хотя typeof NaN — "number". Проверяйте его через Number.isNaN: NaN не равен самому себе. Пустая строка и строка из пробелов преобразуются Number в 0; решение о допустимости пустого ввода принимает программа.

Унарный минус меняет знак: -value, в отличие от value - 1. Деление на ноль в JavaScript не вызывает исключение: возможны Infinity и NaN. Если нужны только конечные числа, используйте Number.isFinite; примеры проверки входа будут в день 2.

```javascript
console.log(Number("18rem"));
console.log(parseFloat("18rem"));
console.log(parseInt("18.7rem", 10));
console.log(+"6.5");
console.log(Number("  "));
console.log(Number.isNaN(Number("нет")));
console.log(-(-8));
console.log(1 / 0);
```

Ожидаемый вывод:

```text
NaN
18
18
6.5
0
true
8
Infinity
```
