# Как читать ошибки

Прочитайте имя ошибки, сообщение, файл и строку. Найдите свою первую строку в стеке вызовов. Причина иногда находится строкой выше указанной позиции.

| Симптом | Что проверить | Как исправить |
| --- | --- | --- |
| SyntaxError | Скобки, кавычки, запятые, структура записи | Свернуть задачу до нескольких строк и восстановить синтаксис |
| ReferenceError: имя не определено | Опечатка, область видимости, объявление | Проверить имя и доступность переменной |
| Cannot access before initialization | Чтение let/const до объявления | Перенести чтение после инициализации |
| Assignment to constant variable | Переназначение const | Решить, нужна ли let, или убрать лишнее переназначение |
| TypeError: ... is not a function | Имя метода, тип значения, случайная замена функции | Вывести typeof и проверить написание |
| Cannot read properties of undefined | Пустой результат find, неверный индекс, отсутствующее поле | Проверить значение до обращения к свойству |
| Получился NaN | Исходные строки, undefined, неудачное преобразование | Проверить вход и Number.isNaN |
| Функция вернула undefined | return отсутствует или не сработал | Проследить все ветки, отличить вывод от возврата |
| Цикл не заканчивается | Условие и изменение состояния | Остановить выполнение и проверить шаг на бумаге |
| Неверный ответ без ошибки | Границы, накопитель, контракт | Найти первый неверный шаг на маленьком примере |

## Порядок отладки

1. Запишите ожидаемый результат.
2. Оставьте минимальный вход, на котором ошибка сохраняется.
3. Посмотрите значения до ошибочной операции: счётчик, текущий элемент, накопитель.
4. Исправьте одну причину.
5. Снова запустите ошибочный пример и прежние проверки.

Не меняйте условие наугад и не скрывайте ошибку пустым catch. Для поиска документации используйте имя ошибки и ключевую часть сообщения без личных данных.
